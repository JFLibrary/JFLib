# IPv4 addresses

A MAC address says who a device is, but not where it stands. To find a destination across many networks, you need addresses with some order in them. That is what IP addresses provide: they are assigned by place in the network, not by manufacturer, and they belong to an interface for as long as they are set up there.

## 32 bits in four numbers

An **IPv4 address** consists of 32 bits. Nobody remembers 32 zeros and ones, so every eight bits are written as one decimal number from 0 to 255, with dots in between:

```text
192      .168      .1        .20
11000000  10101000  00000001  00010100
```

Each place in such a group of eight has its value: 128, 64, 32, 16, 8, 4, 2, 1. The 20 in the last group is 16 + 4, so `00010100`. You will seldom have to work this out by hand, but it explains why 255 is the largest number and why the masks in the next lesson have such odd values.

## Network part and host part

An IP address has two parts, like a postal address with street and house number:

- The **network part** (the leading bits) says which network the device stands in. It is the same for all devices in that network.
- The **host part** (the trailing bits) tells the devices inside the network apart.

![An address as a strip of 32 boxes: the network part on the left, the host part on the right](img/adresse-en.svg)

This split is the real idea. A router somewhere in the network does not need to know every single host; it is enough to know in which direction a network lies. Just as a post office in Hamburg only has to know that a letter is going to Munich, not who lives in which street.

Where the border between the parts lies is not written in the address itself. The mask says that, and it is the topic of [the next lesson](step:maske).

## Special ranges

Some ranges are set aside for particular purposes:

- **Private addresses:** 10.0.0.0 to 10.255.255.255, 172.16.0.0 to 172.31.255.255 and 192.168.0.0 to 192.168.255.255. They are free for your own network and are not forwarded on the internet. The labs of this course use them.
- **Loopback:** 127.0.0.1 is the device itself; every device has this address. A packet sent there never leaves the device.
- **0.0.0.0** means, depending on where it stands, "no address yet" or, in a routing table, "everything".

Setting up an address by hand goes like this; `/24` is the mask of the next lesson:

`ip addr add 192.168.1.20/24 dev eth0`

A device can have several interfaces, and each gets its own address. A router lives on that: it has one in each of its networks.

Besides IPv4 there is IPv6 with 128 bits, because 32 bits became too few for the world. The simulator can do both, and this course stays with IPv4; the ideas carry over.
