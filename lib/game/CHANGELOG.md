# Changelog of jflib-game

What changed in this crate. All of JFLib's crates share one version and are released together;
the [library's changelog](https://github.com/JFLibrary/JFLib/blob/main/CHANGELOG.md) has the
whole picture. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/),
versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as JFLib's
[VERSIONING.md](https://github.com/JFLibrary/JFLib/blob/main/docs/VERSIONING.md) describes.

## [Unreleased]

First release on crates.io.

### Added

- The game core (G7b part 1): `World` (entities with a generation: a stale id is refused or finds nothing; components in dense columns per type, `SparseSet` with a paged index, a version per change and `changed_since`, `Mut` stamps only on a write; `spawn_with`, `despawn`, `insert`, `remove`, `get`, `get_mut`, `column`, `column_mut`, `pair_mut`, `sort_columns` for the canonical order; no archetypes, no scheduler, no hash maps), `Pose` (a `Transform` in f64 now and at the start of the tick, `interpolate(alpha)`, `teleport`; `World::begin_tick` settles only the poses written in the tick before), `FixedTick` (60 Hz unless set, an exact accumulator in nanoseconds times the rate, a cap on catch-up steps, `alpha`, time from outside), `Systems` (functions in a fixed order), `Game` (world, resources, systems, clock). `Input`: `ActionMap` with Button, Axis and Motion actions bound to keys by their place (`Source::Key(KC_*)`), mouse buttons, the wheel and the raw motion; `MouseSettings` (sensitivity in steps of 0.022 degrees a count, Quake's and Source's m_yaw; inversion, a factor per platform: `platform_motion_factor`, `FACTOR_*`); the click that asks for the pointer lock fires nothing, the end of the lock is the game's pause; presses counted per frame and per tick (`tick() -> TickInput`); capture for a settings page; `plat_event` for a game with its own window; `store` / `load` in a `base::Ini` (the free part of `base::Settings`). Cameras in f64: `FirstPerson`, `Follow` (an orbit, `view_in` pulls the eye in front of walls through lib/physics), `FreeFly`, `View`. docs/GAMECORE.md

### Changed

- The netcode's matches over netchan's ClientEvent and ServerEvent take the new events with a _ arm (it does not use the reliable channel)

### Fixed

- net: a count of 0xFFFFFFFF in a peer's inputs or events no longer overflows on 32-bit targets
- Assets::reload keeps the value until the new one has come, as documented: get() gave None while it loaded, and for good when the file did not decode; a reload that fails keeps the old value without a change

[Unreleased]: https://github.com/JFLibrary/JFLib/compare/v0.2.1...HEAD
- The netcode (G7e part 1, `game::net`, over lib/netchan): `NetServer` and the trait `RoomSim` (rooms by code, a fixed tick, every player's input of the tick or the last one repeated, snapshots every two ticks as deltas against what each client holds: the newest it confirmed over UDP, the last sent over a WebSocket, the map's baseline before; quantised fields, changes ordered by an accumulated priority and cut to 1200 bytes since netchan does not fragment; a join's full state that does not fit a datagram is filled in by priority over the next snapshots, or with `ServerOptions::fetch_full` fetched over a WebSocket of its own with a ticket); `NetClient` (ticks ahead of the server on a clock steered by the margin of its inputs, inputs sent with the ones the server may lack, prediction and reconciliation with `Movement` and `Predictor`, the others interpolated 100 ms behind the newest snapshot); lag compensation (`HitHistory`, `view_time`, `hitscan`: the others rewound to what the shooter saw, at most 300 ms); `RoomCode`, room links, names; the bit stream, quantisation grids, the messages; `sim::SimNet` (netchan's cores on a virtual clock with delay, jitter, loss and reordering); `link::serve` and `NetLink` on real sockets; a reference game (`walker::Walker`, `arena::Arena`, `bot::Bot`). Everything a client predicts computes the same bits as the server. docs/NETCODE.md
- (G7a part 2) Game pads in the input actions: `Source::PadButton` (`plat::PAD_*`), `PadAxis` (a stick's axis) and `PadDir` (a stick's direction as a button, with hysteresis) with names for the settings file (`PadA`, `PadLeftX`, `PadLeftX-`), German labels by the pad's style (`label_for(PadStyle)`), `is_pad`; an Axis adds a stick's or a trigger's analog value times the scale, a Motion turns with a stick at `TURN_RATE` (180 degrees a second) x sensitivity with a response curve; `PadSettings` (sensitivity, a radial `dead_zone`, `curve`, `invert_x`, `invert_y`; `stick`, `look`, `store` / `load` beside the mouse's in the same section); `Input::pad_frame(pads, dt)`: the pad used last drives the input (a stick only when none does; `pin_pad` for a split screen), a pad button plays without the pointer lock and fires nothing (`pad_playing`), the mouse still asks for the lock, the lock taken ends pad play, the active pad gone during it pauses, a button held through a pause counts after its release, a tap between two frames is a press and a release; `active_pad`, `pinned_pad`, `device()` (`Device::KeyboardMouse` / `Pad`), `pad_held`, `pad_stick`, `pad_settings`, `set_pad_settings`; `plat_event` takes `E_GAMEPAD`. docs/GAMECORE.md
- Reliable events in the netcode (`game::net::event`): one numbered sequence per direction, every SNAPSHOT and INPUT carries the oldest unacknowledged events up to `ServerOptions::event_budget` / `ClientOptions::event_budget` (Quake 3's reliable commands: delivered once and in order over UDP and WebSocket, no extra packet, no timer); `RoomSim::on_event` and `take_events` with `RoomEvent` / `To::{All, Player, AllBut}`, `NetServer::send_event`, `NetClient::send_event` / `take_event`; a client that leaves 512 events unacknowledged is dropped. The bit EXT in byte 0 marks the event part: without events the messages are those of protocol version 1 (docs/NETCODE.md)
- Leaving a room: LEAVE (protocol version 2), `NetClient::leave` (`Phase::Left`), `NetLink::leave` (LEAVE, then netchan's DISCONNECT): the server removes the figure at once (`ServerStats::left`)
- Smoothed corrections: `predict::Smoother` turns the jump of the own figure at a reconciliation into an offset of the drawn position that decays in `ClientOptions::smooth_ms` (60) and snaps above `snap` (1 m); `NetClient::drawn`, `smoothing`; the prediction stays bit for bit the server's
- Rooms side by side: `NetServer::set_parallel` runs the rooms of a tick on plat's worker pool and merges their messages in the order of the room codes (the same bytes as on one thread); room codes and tickets from the system's random numbers with `NetServer::secure` / `with_random` (a seeded xorshift gave its state away with one ticket)

### Changed

- A client over a WebSocket aims for one tick more input margin (`ClientOptions::stream_margin`, set by `NetClient::set_reliable`, which NetLink calls): measured over WLAN, 2.7 instead of 12 corrections a minute
- (G7b part 2) Assets: `game::assets` -- `Assets<T>` loads files through the VFS and decodes them in the background (`Loading::Background` on plat's blocking pool, `Loading::Frames { budget_us }` within a budget per update: the browser without threads, deterministic tests), behind `Handle<T>` with a state (`Loading`, `Ready`, `Failed`), counted references and unloading (`update() -> Vec<Change>`, `set_linger`, `reload`, `insert`, `wait_idle`); kinds are types (`Asset::decode`, `Bytes`). Spatial audio: `game::audio` -- `SpatialAudio` over plat::audio's mixer with a listener (the camera's `View`), `Emitter` components and sounds at points (`play_at`), `Attenuation` (linear, OpenAL's inverse distance clamped) and an equal-power pan; `Mixer`: `Speakers` or plat's `MixTest`. docs/GAMECORE.md
