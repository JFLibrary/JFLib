What changed in this crate. All of JFLib's crates share one version and are released together;
the [library's changelog](https://github.com/JFLibrary/JFLib/blob/main/CHANGELOG.md) has the

## [Unreleased]

First release on crates.io.

### Added

- DXF in the ASCII format of R12 to 2018 into a model without a GPU -- the header's variables, the tables of layers (index and true colour, linetype, lineweight, off, frozen, transparency), linetypes (dash patterns; complex elements kept as flags and texts), text styles, block records and dimension styles, blocks with their entities, and the entities of the drawing (LINE, POINT, CIRCLE, ARC, ELLIPSE, SPLINE and HELIX, LWPOLYLINE and POLYLINE with bulges, widths, 3D polylines and meshes, TEXT, ATTRIB, ATTDEF, MTEXT with R2018's and R2007's columns, INSERT with MINSERT's array and its attributes, HATCH with every kind of boundary edge and its pattern's line families, SOLID, TRACE, 3DFACE, DIMENSION and ACAD_TABLE through their blocks, LEADER, WIPEOUT, RAY, XLINE; other kinds counted by name). `dxf::load` keeps a whole file, `dxf::read` streams it through a `Sink` and keeps only tables and blocks (a file of a gigabyte in bounded memory). Strings before AC1021 in the header's code page (the single-byte pages, generated by tools/gen_dxf_codepages.py), UTF-8 after, \U+XXXX everywhere; `mtext::parse` (MTEXT's inline format codes as paragraphs of runs), `specials` (TEXT's %% codes), `aci_rgb` (AutoCAD's colour index), `font_substitute` (which repository font stands in for an SHX or TrueType font). Files are untrusted input: `Limits` bounds lines, the pairs, bytes and points of an entity and what is kept, counts in a file never size an allocation, nothing recurses, a broken file gives what came before the break; a binary DXF is Error::Binary. docs/RENDER2D.md section DXF

### Changed

- `$DWGCODEPAGE` is decoded with jflib-formats' character sets (`formats::encoding::Charset`) instead of tables of its own: ANSI_n and DOSn by their code page (so DOS737, 775, 858 and 862 have tables now), MACINTOSH, a few ISO-8859 and KOI8-R by name. Changed bytes: in the ANSI pages an unassigned byte of 0x80..0x9F is the C1 control of the same number (as Windows reads it) instead of U+FFFD; ISO8859-9 is windows-1254 (its punctuation in 0x80..0x9F).
